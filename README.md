Система управления розницей

# STAFF (Site + Telegram Bot) — staff.yago-app.ru

Этот репозиторий — **отдельный проект** (не связан с основным `yago-app.ru`).
Внутри — **две части одного продукта** с общей базой:

1) **Telegram Bot** — главный интерфейс для регистрации и работы персонала  
2) **Site (staff.yago-app.ru)** — **только для входа владельца** (owner) в веб-кабинет

⚠️ Важно:  
- **Владелец регистрируется ТОЛЬКО в боте**, а **входит на сайте** (по данным/токену, которые получит после регистрации).  
- **Сотрудник к сайту вообще не относится** и работает **только в боте**.

---

## 1) Продуктовая логика (как это работает)

### 1.1 Роли
- **Owner (владелец организации)**  
  - регистрируется **в боте**
  - затем **входит на сайте** в личный кабинет
  - управляет организацией (сотрудники и т.д.)
- **Employee (сотрудник)**  
  - работает **только в боте**
  - привязывается к организации по инвайт-коду

### 1.2 Регистрация владельца (только Bot)
Сценарий:
1) Владелец запускает бота
2) Выбирает **“Я владелец”**
3) Проходит регистрацию
4) Создаётся **Organization**
5) Организации выдаётся **Invite Code**
6) Владелец получает свои **данные для входа на сайт** (или ссылку/код/токен — зависит от реализации)

### 1.3 Регистрация сотрудника (только Bot)
Сценарий:
1) Сотрудник запускает бота
2) Выбирает **“Я сотрудник”**
3) Вводит **Invite Code**
4) Сотрудник привязывается к Organization

### 1.4 Site (только Owner login)
На сайте **нет регистрации**.
Там есть:
- **форма входа владельца**
- после входа владелец видит свою организацию и управление

### 1.5 Кабинет владельца (будущий функционал)
После входа владелец сможет:
- видеть организацию
- видеть список сотрудников
- управлять доступами/приглашениями (инвайт-код)
- далее функционал будет расширяться

### 1.6 Bot (сотрудник)
Сотрудник в боте сейчас/первым этапом видит:
- **Профиль**
- **Рецепты** (раздел с кнопками)

Далее бот будет обрастать: обучение, смены, задачи, тесты и т.д.

## 2) Архитектура (в двух словах)

- Bot и Site используют **общую БД**:
  - Users
  - Organizations
  - Membership (связь сотрудника с организацией)
  - Invite Code

Site не нужен сотруднику: все действия сотрудника — **только Bot**.

## 4) Секреты и где они хранятся

### ВАЖНО: секреты не храним в коде/репозитории
Секреты хранятся **в GitHub Secrets** (Repo → Settings → Secrets and variables → Actions).

#### Обязательный секрет
- `TG_BOT_TOKEN` — токен Telegram бота (из BotFather)

#### Позже (когда подключим БД)
- `DB_URL` — строка подключения к базе данных

В коде секреты читаются только через:
- `process.env.TG_BOT_TOKEN`
- `process.env.DB_URL`

### Хранение данных (owners/employees/companies)
По умолчанию данные сохраняются в `data/db.json` рядом с кодом.  
Чтобы данные не терялись при деплое, можно указать путь вне репозитория:
- `DATA_DIR` — директория для `db.json` (например, `/var/lib/staff.yago-app`)
- `DB_PATH` — полный путь до файла БД (переопределяет `DATA_DIR`)

6) Production (VPS)
6.1 Домен и порт

Site доступен по: https://staff.yago-app.ru

Nginx проксирует на: http://127.0.0.1:4101

SSL: Let’s Encrypt

6.2 Процессы PM2 (обязательно 2)

staff-site — site (вход владельца)

staff-bot — bot (регистрация владельца + работа сотрудников)

7) Автодеплой (GitHub Actions)

Триггер: push в main.

Workflow делает:

rsync кода на сервер в /var/www/staff.yago-app.ru

установка зависимостей (npm install / npm ci)

сборка (npm run build --if-present)

перезапуск процессов:

pm2 startOrReload ecosystem.config.js

Дополнительно создаётся:

version.txt (SHA + время), чтобы видеть, что обновление применилось.

Проверка на сервере:

cat /var/www/staff.yago-app.ru/version.txt
pm2 list

8) Диагностика (VPS)
Процессы
pm2 list

Логи сайта
pm2 logs staff-site --lines 100

Логи бота
pm2 logs staff-bot --lines 100

Проверка сайта локально на VPS
curl -i http://127.0.0.1:4101/health

Nginx ошибки
sudo tail -n 100 /var/log/nginx/error.log

9) Правила, чтобы ничего не ломалось

В деплое никогда не использовать pm2 stop all / pm2 delete all (на сервере есть другие проекты).

Один порт = один процесс. 4101 — только staff-site.

Токены/пароли — только GitHub Secrets, не в коде.

Site — только owner login, без регистрации.

Employee — только bot, сайт не используется.
